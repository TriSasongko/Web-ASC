# AGENTS.md

Laravel 13 + Breeze (Blade) app for an Indonesian soccer academy (ASC). PHP ^8.3, MySQL for local dev, Tailwind v3 + Alpine on the frontend. No Vue/React.

## Commands

- Dev servers: `composer dev` (runs `php artisan serve` + queue:listen + `php artisan pail` + Vite concurrently). Asset-only: `npm run dev` / `npm run build`.
- Tests: `composer test` (clears config, then `php artisan test`). Single test: `php artisan test --filter=TestName`. Tests use in-memory sqlite (phpunit.xml) — they never touch MySQL.
- Format: `vendor/bin/pint` (default Laravel preset).
- DB setup: `php artisan migrate --seed` (`DatabaseSeeder` = `RoleUserSeeder` + `ProgramSeeder` + `DummyDataSeeder`). Seeded logins (all password `password`): `admin@asc.test` (admin), `pelatih@asc.test` (coach), `ortu@asc.test` (parent); `DummyDataSeeder` also adds `coach1..N@asc.test` / `parent1..N@asc.test` with students. `ProgramSeeder` seeds the 5 programs.

## Gotchas

- `.env.example` points to sqlite, but the real local `.env` uses **MySQL** (`asc_website`, root, no password). `composer setup` is the sqlite fresh-install path only. Create the MySQL DB and run `migrate --seed` for real dev.
- **3 pre-existing test failures are expected**: `AuthenticationTest::test_users_can_authenticate_using_the_login_screen` and two `ProfileTest` email-verification tests. Cause: `UserFactory` does not set `role` (migration defaults to `orang_tua`) and `/dashboard` redirects by role. When adding tests, set `role` explicitly via `User::factory()->create(['role' => 'admin'])`.
- `.npmrc` sets `ignore-scripts=true`; `@rolldown/binding-win32-x64-msvc` is pinned in package.json to provide the native Vite binding. Don't remove it.
- **Renewal flags are real-time, not scheduler-driven**: `renewal:check` is scheduled daily in `routes/console.php`, but `composer dev` does NOT run the scheduler. Both `Admin/AttendanceController` and `Pelatih/AttendanceController` call `ClassStudent::markForRenewalIfNeeded()` (and `completeRenewalIfReady()`) after recording attendance; run `php artisan renewal:check` manually to backfill. When recording attendance on a `per_paket` enrollment whose active period is already finished with status `lanjut`, the controller first calls `completeRenewalIfReady()` to open the next period so the attendance lands on the **new** package (recap shows each package separately). In the admin recap (`admin/students/show`), a non-active period of a class that still has an active period renders as a collapsed **Riwayat** card (attendance hidden behind a "Lihat" toggle); the active period's attendance is shown by default.
- **Seeded `Attendance` rows have `class_student_id = NULL`** (seeders predate the period backfill). `StudentController::show` re-attaches legacy rows to a period via a date-window fallback (`periodContains()`). Preserve this logic.
- **Attendance is unique per student per day** — DB index `unique_attendance_per_day` on `(student_id, attendance_date)` (replaces the old `(student_id, attendance_date, session_number)`; `session_number` is always 1). Both `store()`s pre-check with `whereDate('attendance_date', ...)` and return a friendly validation error listing students already recorded; use `whereDate`, not `where`, or the check silently misses on SQLite (date is stored with a time component there). The shared form (`attendance-student-form.blade.php`) gets an `$attendanceByDate` map from `create()` and disables checkboxes for already-recorded students per selected date via Alpine.

## Architecture

- **Three roles** stored as an enum `role` column on `users` (`admin`, `pelatih`, `orang_tua`), default `orang_tua`. Helpers: `User::isAdmin()/isPelatih()/isOrangTua()`. Users also have `phone`, `address`, `is_active` (inactive users are logged out by `CheckRole`).
- **Role-gated routes** via `role:` middleware alias (`app/Http/Middleware/CheckRole.php`), grouped by prefix in `routes/web.php`: `/admin/*`, `/pelatih/*`, `/orangtua/*`. `/dashboard` dispatches to the role's dashboard. New features go in the matching role group.
- **Models**: `User` → `Student` (parent_id) → `class_student` pivot → `SchoolClass` (program_id, level; **no student capacity** — the `capacity` column is dormant/unused in code; **no `coach_id`** — coaches attach to `ClassSchedule` via `class_schedule_user`, many-to-many) → `Program` (`billing_type` `per_paket`/`per_bulan`; Kompetitif is `per_bulan` with `total_sessions = null`). Plus `ClassSchedule` (`class_schedule_student` pivot), `Attendance` (status `hadir`, `recorded_by`), `Development` (per-student evaluations), `CoachNote` (pelatih's private notes, sorted by `note_date`), `ClassRecommendation` (promotion — **two entry points, both require parent confirmation**): pelatih proposes (`pending`) → admin `approve` → `menunggu_ortu`; OR admin initiates from a class page via `admin.class-students.move`, which creates the rec straight in `menunggu_ortu` (no `pending` step). Either way the student is moved only by `admin.recommendations.confirm` (after the parent agrees via WA), which calls `StudentPromotionService::promote()`. **Promotion rules**: current `per_paket` package must be finished (`isFinished()`), enforced in `promote()` + both recommendation `store()`s + `move()`; max one active rec per student (`pending`/`menunggu_ortu`); `promote()` deactivates the old enrollment (`renewal_status=pindah`) and creates a new Kompetitif enrollment with `started_at = now()` — leftover sessions don't carry over.
- **Renewal/period model** (non-obvious): one `class_student` row = one package **period**. The old unique `(class_id, student_id)` constraint is dropped — a student has multiple period rows per class, only one `is_active` (enforced in app code, not DB). `renewed_from_id` chains periods; `started_at`/`ended_at` bound each. `renewal_status` enum: `belum_konfirmasi`, `lanjut`, `berhenti`, `pindah`, `perlu_konfirmasi`, `selesai`, `aktif`. Flow: `perlu_konfirmasi` → admin confirms (defer to `lanjut` if sessions remain, else `renewIntoNextPeriod()` creates the next period) or declines (`berhenti`). **`admin.class-students.renew`** (the "Perpanjang Paket" button in the admin student recap) now mirrors `confirmRenewal`: defer to `lanjut` when `remainingSessions() > 0` (counter is NOT reset), else `renewIntoNextPeriod()`. The old buggy behavior (reset `sessions_completed` to 0 on the same period and set `lanjut`) created unattached attendances and stalled counters on real data — do not reintroduce.
- **`Student` has a global scope** `ActiveParentScope` that excludes students whose parent `is_active` is false. Use `withoutGlobalScope(ActiveParentScope::class)` if you must query them.
- **Development entry is gated** by `User::canAssessDevelopments()` (`can_assess_developments` column), not by role alone; coach dashboard/`create` pages branch on it.
- **Admin developments index groups 1 row per student** (a child has one `Development` per period, e.g. "Juli 2026", "Agustus 2026"): `Admin\DevelopmentController@index` paginates `Student` (with `developments` eager-loaded latest-first) instead of `Development` rows. The index shows no period column — "Lihat Perkembangan" opens the per-student history page (`admin.classes.developments.history`), which lists every period as a tab (each tab has its own E-Raport + delete). Row actions link to the latest period.
- **Controllers/views mirror role dirs**: `app/Http/Controllers/{Admin,Pelatih,OrangTua}` and `resources/views/{admin,pelatih,orangtua}`.
- **E-Raport PDF**: `ERaportController` uses `barryvdh/laravel-dompdf` (`Pdf::loadView('eraport.pdf')`). Shared by admin + parent; parents are restricted to their own children inside the controller (`authorizeAccess`), not via middleware.
- **Admin student index** filters by `?status=` (`semua|aktif|perlu_konfirmasi|berhenti|pindah`, default `aktif`) via the `enrollments` relation; always keep the `whereHas('registrations', 'diterima')` base.

## Conventions

- UI text, comments, and route names are in **Indonesian** (`pelatih` = coach, `orang_tua` = parent). Keep it that way.
- `UserFactory` intentionally omits `role`; set it explicitly in tests.
